# Workflow Atlas & Graph — Handoff

Two views of one workflow dataset, in the Hearth v2 design system. Both live in `directions/hearth/`.

## Files

| File | Role |
|---|---|
| `wf-graph-data.js` | **Single source of truth** — workflows, their steps, step-level transitions, and value-stream phases. Both pages read this. |
| `wf-elk.js` | Layout helpers: `layoutFull()` (Graph) and `layoutCondensed()` (Atlas). |
| `wf-panzoom.js` | Shared `usePanZoom` hook (drag-pan, wheel/pinch zoom, fit). Plain JS, uses global React. |
| `atlas.html` + `atlas-app.jsx` | **The Map** — value-stream summary. |
| `atlas-graph.html` + `atlas-graph-app.jsx` | **The Graph** — full topology with steps. |

Both pages: React 18 + in-browser Babel, ELK from `unpkg.com/elkjs@0.9.3/lib/elk.bundled.js`, the Hearth component library (`lib/*`, `AppShell` from `lib-shell.jsx`), `tokens.css`, `components-v2.css`, `lib/components-lib.css`. Map/Graph toggle links the two.

## Data model (`wf-graph-data.js`)

- **workflows[]**: `{ id, name, status, statusLabel, desc, phase, runs24h, avg, live?, steps[] }`
  - **steps[]**: `{ id, name, kind, role }` — kinds: `entry · execute · eval · route · wait · human · final`
- **edges[]**: every transition is **step-level** — `{ from: 'wfId.stepId', to: 'wfId.stepId', label }`
  - cross-workflow = different workflow ids; loop-back = same workflow, target step earlier in order
  - forward step→step links are *implied by step order* and generated by the layout helper (not listed)
- **phases[]**: `['Intake','Build','Verify','Review','Ship']` — the value-stream column order. Each workflow declares its `phase`.

Add a workflow/edge/phase here and both pages reflow automatically.

## The Graph page — `layoutFull()` (ELK)

- ELK **nested** layout: workflow **containers** with **step nodes** laid out left→right inside; containers arranged top→down by the cross-workflow DAG.
- `SEPARATE_CHILDREN` (each container self-lays-out its steps).
- **Cross-workflow edges route container→container** (ELK won't reliably route edges that reference *deep* step children under SEPARATE; and `INCLUDE_CHILDREN` flattens the hierarchy and breaks per-container step direction — the staircase bug).
- **Loop-backs are kept OUT of ELK's node placement** (so step rows stay clean) and drawn as green arcs under each step row from the resolved step positions.
- Orthogonal routing, condition labels, **hover a container to trace** its handoffs (lights its edges, dims the rest), pan/zoom, Labels toggle.

## The Atlas page — `layoutCondensed()` (deterministic)

- **Columns = phases (from data)**, NOT ELK. Members stacked + vertically centered per column.
- Custom orthogonal router: verticals ride the column gaps; long hops ride **top/bottom corridors**; same-column edges use a **left side-bus** — so edges never cross a card.
- Step edges aggregated up to workflow→workflow for the condition labels.
- **Step-grouping modes** inside each card (switchable): `Ribbon · Pipeline · Grouped (run-length) · Tally (composition)`.
- Rich cards (name, live ember badge, grouped chips, `N steps · X/24h · avg`), condition chips, hover-trace, search, pan/zoom.

## Key decisions & gotchas (so you don't relearn them)

1. **elkjs runs in-sandbox** via `new ELK()` (bundled build, no web worker needed).
2. **ELK `INCLUDE_CHILDREN` flattens the hierarchy** → the root's DOWN direction overrides each container's RIGHT (steps staircase). Use `SEPARATE_CHILDREN`.
3. **Under SEPARATE, ELK won't route edges to deep child nodes** → route cross-workflow edges at the **container level**.
4. **ELK can't pin a phase to a single column** when that phase has internal edges — `partitioning` *and* `layerChoiceConstraint` both sub-layer it (Build chain, Verify pair). That's why the Atlas uses a **deterministic** column layout, not ELK.
5. **Stages must be real data.** Earlier they were ELK topological-layer indices labeled "Stage NN" — misleading. Now they're the `phase` field.

## Caveats / open follow-ups

- `runs24h` / `avg` on cards are **placeholder sample data**; `phase` is a real structural field.
- ELK + JSX load from CDN / in-browser Babel — **vendor ELK and precompile JSX for production.**
- Graph cross-edges land **container→container**, not on the exact step (step-exact endpoints are a possible follow-up via a separate INCLUDE_CHILDREN routing pass / hierarchical ports).
- Neither page is **wired into the Design page nav** yet — natural next step is a Map / Graph (/ Canvas) mode switch on the Design page.
- The Atlas router is heuristic (corridor lanes staggered by edge index); robust for this set, but very dense phases may need lane tuning.
