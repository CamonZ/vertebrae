Floating
panels.

The detail panel is the most-used surface in Vertebrae. Workflows, steps, and tasks each have their own kind of detail — and users often need to cross-reference them. Four patterns for how that could work, with the trade-offs each one carries.

The three detail entities
Workflow

The pipeline. Lives at the top; defines the steps and the transitions.

workflow / a1b2c3d4
Step

A node in the workflow. Carries instructions, agent config, transitions out.

step / execute / i9j0k1l2
Task

A unit of work. Most-opened entity. Carries spec, acceptance criteria, runs.

task / m3n4o5p6

One panel,
replaces on click.

The current spec. A single right-docked panel that swaps content as you click around. Simple, predictable — but loses context when comparing two things.

Option C · tabbed inspector

One panel,
many tabs.

A single panel slot, but multiple open entities live as tabs. New selections open as a new tab (Cmd-click) or replace the active tab (plain click). Tabs are color-coded by entity kind.

Option D · detachable float

Dock by default,
tear off to float.

Panels open docked. Drag the header (or hit ⌘⇧O) and a panel detaches into a floating, draggable card. Re-dock by snapping near the right edge. Floats persist position; multiple can be open anywhere on the canvas.

Pros

  • Free-form — users arrange panels around the work
  • Mix docked + floating: keep the most-used panel anchored
  • Position survives reload (per-entity stored)
  • Best for power users who run multi-monitor

Cons

  • Most complex to build — drag, snap, store, restore
  • Discoverability: users may not realise panels can detach
  • Floating panels can occlude the canvas they describe
  • Mobile / narrow viewports degrade ungracefully
Recommendation

Ship B → C in sequence;
add D as a power-user gesture.

Option B (multi-pane stack) is the highest-value next step. It directly addresses the "I just need to peek at the parent" complaint without inventing a new mental model: click drills, ✕ pops. Build this first.

  • Phase 1. Ship Option B. The stack handles 2–3 panels well, which covers ~95% of cross-reference needs (task ↔ step, task ↔ workflow).
  • Phase 2. Add tabs (Option C) as a tab bar inside the rightmost stack slot, so a single panel slot can hold multiple peer entities (e.g. comparing two tasks at the same step).
  • Phase 3. Expose detach (Option D) via ⌘⇧O and a header drag-handle. Most users never touch it; power users live in it.
